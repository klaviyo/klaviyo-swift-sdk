# Profiles and Events

Identify the current user, track what they do in your app, and subscribe them to lists.

## Overview

The SDK identifies your users as Klaviyo profiles, records the events they perform, and creates list
subscriptions with consent records. It persists profile identifiers to local storage, so it keeps
track of the current profile for you when you create events or set a push token.

## Identify a profile

The SDK identifies users through the
[Create Client Profile API](https://developers.klaviyo.com/en/reference/create_client_profile). A
profile can be identified by any combination of:

- **External ID:** a unique identifier that associates the Klaviyo profile with a profile in an
  external system, such as a point-of-sale system. Its format depends on the external system.
- **Email address**
- **Phone number** in [E.164 format](https://help.klaviyo.com/hc/en-us/articles/360046055671#h_01HE5ZYJEAHZKY6WZW7BAD36BG)

You can set profile identifiers all at once with ``KlaviyoSDK/set(profile:)`` or one at a time with
``KlaviyoSDK/set(email:)``, ``KlaviyoSDK/set(phoneNumber:)`` and ``KlaviyoSDK/set(externalId:)``.
Either way, the SDK groups and batches API calls to improve performance.

```swift
// Organization, title, image, location and additional properties (a dictionary)
// can also be set with this initializer.
let profile = Profile(email: "junior@blob.com", firstName: "Blob", lastName: "Jr.")
KlaviyoSDK().set(profile: profile)

// Or set individual properties.
KlaviyoSDK().set(profileAttribute: .firstName, value: "Blob")
KlaviyoSDK().set(profileAttribute: .lastName, value: "Jr.")
```

See ``Profile`` and ``Profile/ProfileKey`` for every attribute you can set.

### Reset the profile

To start a new profile altogether, for example when a user logs out, either call
``KlaviyoSDK/resetProfile()`` to clear the currently tracked profile identifiers, or call
``KlaviyoSDK/set(profile:)`` to overwrite them with a new ``Profile``.

```swift
// Start a profile for Blob Jr.
let blob = Profile(email: "junior@blob.com", firstName: "Blob", lastName: "Jr.")
KlaviyoSDK().set(profile: blob)

// Stop tracking Blob Jr.
KlaviyoSDK().resetProfile()

// Start a profile for Robin Hood.
let robin = Profile(email: "robin@hood.com", firstName: "Robin", lastName: "Hood")
KlaviyoSDK().set(profile: robin)
```

## Anonymous tracking

Klaviyo tracks unidentified users with an autogenerated ID whenever a push token is set or an event
is created. That way you can collect push tokens and track events before you collect profile
identifiers such as an email address or phone number. When you provide an identifier, Klaviyo merges
the anonymous user into the identified user.

> Note: If you enable the `klaviyo_automatic_push_token_forwarding` opt-in flag (see
> <doc:MigrationGuide#Migrating-to-v540>), the SDK forwards the device push token to Klaviyo
> automatically once APNs delivers it to your app. That only happens after your app calls
> `registerForRemoteNotifications()`. Because this can happen before you call
> ``KlaviyoSDK/set(profile:)``, ``KlaviyoSDK/set(email:)`` or ``KlaviyoSDK/set(phoneNumber:)``,
> Klaviyo creates an anonymous profile until you provide identifying information. This is expected.

### Avoid anonymous profiles

If your app should never create a profile in Klaviyo until the user is known (email, phone number or
external ID), initialize the SDK as usual and hold back the calls below until after you call
``KlaviyoSDK/set(email:)``, ``KlaviyoSDK/set(phoneNumber:)`` or ``KlaviyoSDK/set(externalId:)``.
This guidance was verified against SDK version 5.4.0.

1. **Leave automatic push token forwarding off.** Don't set
   `klaviyo_automatic_push_token_forwarding` to `true` in `Info.plist`. It's off when absent.
2. **Before identifying the user, don't call:**
   - `set(pushToken:)`
   - ``KlaviyoSDK/create(event:)``
   - ``KlaviyoSDK/set(profileAttribute:value:)``, or ``KlaviyoSDK/set(profile:)`` with no email,
     phone number or external ID
   - `registerForInAppForms()` (see [In-App Forms](/documentation/klaviyoforms/inappforms))
   - `registerGeofencing()` (see [Geofencing](/documentation/klaviyolocation/geofencing))
   - ``KlaviyoSDK/handleUniversalTrackingLink(_:)``
3. **After identifying the user,** call `set(pushToken:)` and register for forms and geofencing as
   normal.

``KlaviyoSDK/handle(notificationResponse:withCompletionHandler:)`` and
`klaviyo_automatic_push_open_tracking` are safe to use at any time. Klaviyo attributes push opens to
the profile the notification was sent to, without creating a new one.

Things to keep in mind:

- **Requests are tagged with identity when they're queued.** Calling ``KlaviyoSDK/set(email:)``
  later doesn't change requests that were already queued, and queued requests persist across app
  launches.
- **Logout and switching users.** ``KlaviyoSDK/resetProfile()`` keeps the push token and registers
  it to a new anonymous profile, so don't call it on logout if you need to avoid anonymous profiles.
  (Personalized in-app forms ask you to reset on logout; see
  [In-App Forms](/documentation/klaviyoforms/inappforms#Personalized-forms-authentication).)
  Instead:
  - On logout, stop making the calls listed above, and call `unregisterFromInAppForms()` and
    `unregisterGeofencing()`.
  - On the next login, call ``KlaviyoSDK/set(profile:)`` with all of the new user's identifiers.
    When the identifiers differ, the SDK starts a fresh profile and sends the stored push token with
    the new identifiers in a single request. Calling ``KlaviyoSDK/set(email:)`` on its own keeps the
    previous user's other identifiers.
  - Until someone logs in again, the previous user's profile keeps this device's push token and can
    still receive pushes on it.
- **Existing installs.** If an earlier version of your app already created anonymous profiles, those
  profiles stay in Klaviyo. A user who later logs in on the same device is merged into their
  identified profile; users who never log in remain anonymous and must be cleaned up in Klaviyo.
  Requests queued by the earlier version still send after the update, and users who don't update
  keep the old behavior.

## Track events

The SDK tracks events that users perform in your app through the
[Create Client Event API](https://developers.klaviyo.com/en/reference/create_client_event). Build an
``Event`` and pass it to ``KlaviyoSDK/create(event:)``:

```swift
// Using a predefined event name
let event = Event(name: .startedCheckoutMetric,
                  properties: [
                      "name": "cool t-shirt",
                      "color": "blue",
                      "size": "medium",
                  ],
                  value: 166)

KlaviyoSDK().create(event: event)

// Using a custom event name
let customEvent = Event(name: .customEvent("Checkout Completed"),
                        properties: [
                            "name": "cool t-shirt",
                            "color": "blue",
                            "size": "medium",
                        ],
                        value: 166)

KlaviyoSDK().create(event: customEvent)
```

### Event arguments

An ``Event`` takes the following arguments:

- `name` (required): the name of the event to track, as an `Event.EventName`. `Event.EventName` lists
  common Klaviyo-defined metrics, such as `.startedCheckoutMetric`. To track a custom event, use the
  `.customEvent(_:)` case.
- `properties`: an optional dictionary of properties specific to the event.
- `value`: an optional numeric value (`Double`) to associate with the event, for example the dollar
  amount of a purchase.

## Subscribe a profile to a list

The SDK can create a subscription and consent record for the email, SMS and WhatsApp channels based
on the profile's email and phone number, through the
[Create Client Subscription API](https://developers.klaviyo.com/en/reference/create_client_subscription).
You must provide either an email address or a phone number. WhatsApp BSUID support is coming soon.

Set the profile's email and/or phone number **before** subscribing. A subscribe call that requests a
channel whose identifier hasn't been set isn't sent: the SDK drops it when you call it and logs a
developer warning.

Profiles can be opted into multiple channels, for example email marketing, SMS marketing and SMS
transactional. Specify the channels to subscribe with the `channels` value on ``Subscription``. If
you include `channels`, only those channels are subscribed. If you use
``Subscription/allAvailableMarketing(listId:customSource:)``, no `subscriptions` object is sent and
subscriptions default to `MARKETING`.

This API doesn't create push notification subscriptions. Register push tokens with `set(pushToken:)`
instead; see <doc:PushNotifications>.

```swift
KlaviyoSDK().set(email: "johnpork@demo.com")
KlaviyoSDK().set(phoneNumber: "+15005550006")

// Subscribe to a list, defaulting to MARKETING consent for every channel
// available from the identifiers you've set:
KlaviyoSDK().create(subscription: .allAvailableMarketing(listId: "XXXXXX"))

// Or request specific channels and consent types:
let subscription = Subscription(
    listId: "XXXXXX",
    channels: .init(
        email: .marketing,
        sms: [.marketing, .transactional],
        whatsapp: [.marketing, .transactional]
    ),
    customSource: "iOS in-app form"
)
KlaviyoSDK().create(subscription: subscription)
```

### Subscription arguments

``KlaviyoSDK/create(subscription:)`` takes a ``Subscription``. Construct one with either:

- ``Subscription/allAvailableMarketing(listId:customSource:)``, which omits the `subscriptions`
  object so the API defaults to `MARKETING` consent for every channel available from the profile's
  identifiers.
- ``Subscription/init(listId:channels:customSource:)``, which sends a `subscriptions` object for only
  the channels you name. `channels` is required on this initializer so that a broad grant is never
  the result of an omitted argument.

``Subscription/Channels`` takes optional `email`, `sms` and `whatsapp` values. Each channel exposes
only the consent sub-types the API supports for it. Pass one value (for example `.marketing`) or
several (for example `[.marketing, .transactional]`). The consent types per channel are:

- `email` (``Subscription/Channels/Email``): `.marketing`, `.openTracking`
- `sms` and `whatsapp` (``Subscription/Channels/Messaging``): `.marketing`, `.transactional`

`customSource` is an optional free-text label that describes where the signup originated, such as a
form or screen name. It's stored as the consent record's source.
